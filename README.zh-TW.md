## v0.1.19 更新內容

拾光 v0.1.19 繼續免費內測，改善經典版的編輯、載入與動效體驗。

- 改善預設編輯的輸入焦點與草稿復原；切換頁面後可繼續編輯，衝突草稿可另存新預設。
- 設定與轉存初始化失敗時提供清楚回饋及重試入口，補齊四語言錯誤說明。
- 保留專案頁上抬與統計卡片依序出現效果，完善授權說明及新建專案外觀選項的展開收起動畫。
- 調整新建專案路徑與外觀選項順序，移除授權卡片收起後多餘的底部空白。
- 設定新增官網、使用指南及 NAS／百度網盤目錄教學入口。

僅提供 Apple Silicon macOS 版本。公開 v0.1.18 可從設定檢查更新；未設定更新通道的舊版或本機開發包，請結束工作、退出 App 後使用 DMG 替換。升級前請備份重要專案與素材。

仍採 ad-hoc 簽署，尚無 Apple Developer ID 簽署或 Apple 公證。既有 NAS SMB 斷線與百度自動同步隔離限制仍在，請保留原卡與另一份可靠備份。

## 拾光可以做什麼

| 功能 | 說明 |
| --- | --- |
| 記憶卡辨識 | 辨識常見照片、影片與音訊素材，依拍攝日期、機位與專案預設整理檔案 |
| 安全轉存 | 依目標磁碟能力選擇安全寫入方式；絕不覆寫同名檔案，異常殘留會保留並明確報錯 |
| 二重備份 | 相機卡只讀取一次，同時寫入工作磁碟與第二顆備份磁碟 |
| 複製檢驗 | 快速檢驗會檢查檔案可讀性與大小；完全檢驗會重新讀取目標檔案，並以 xxHash64 與來源素材比對 |
| 報告與防止重複轉存 | 產生 MHL 與人類可讀報告，記錄已成功轉存的卡片，補轉存時只處理新增或缺少的檔案 |
| 專案與預設 | 用可重複使用的資料夾範本建立專案，統一原始素材、選片、成品、音訊與工程檔案結構 |
| 專案封存 | 封存時執行完全檢驗，保留專案記錄與監管鏈，不會自動刪除本機素材 |

## 如何理解檢驗

- **不檢驗**：只根據寫入過程是否報錯，速度最快，不適合重要素材。
- **快速檢驗**：逐一檢查檔案是否存在、可讀，以及位元組數是否一致，用來發現遺漏或明顯截斷。
- **完全檢驗**：從每個目標磁碟重新讀取所有位元組，重算 xxHash64 並與複製時的來源雜湊值比對，適合重要拍攝或二重備份流程。

xxHash64 在這裡用來檢測複製內容是否一致，不是身分驗證或加密簽章。即使檢驗通過，也建議在格式化相機卡前人工抽查關鍵素材，並確認至少兩份副本可用。

## macOS 首次開啟

v0.1.19 尚未使用 Apple Developer ID 簽署，也尚未通過 Apple 公證。macOS 可能因此擋下首次啟動：

1. 只從 [Sorasukiawa/shiguang](https://github.com/Sorasukiawa/shiguang) 的 Releases 下載 DMG。
2. 開啟 DMG，將「拾光」拖曳到「Applications / 應用程式」資料夾。
3. 從「應用程式」正常開啟一次；若系統阻擋，先關閉提示。
4. 前往 **系統設定 → 隱私權與安全性**，確認被阻擋的應用程式是「拾光」後，選擇「強制打開」。

不需要關閉 Gatekeeper，也不要為來源不明的安裝檔繞過系統保護。

## 儲存磁碟相容性

- **APFS 是工作磁碟、第二顆備份磁碟與封存目標磁碟的建議格式。**
- **ExFAT 也可作為目標磁碟，但必須先通過拾光的安全能力實測。**無法證明安全時，應用程式會在寫入素材前拒絕，不會降級成可能覆寫檔案的普通寫入。
- **ExFAT 相機卡可直接作為唯讀素材來源**，不受目標磁碟的安全測試限制。

APFS 與 ExFAT 使用不同的安全寫入方式，但都不會覆寫現有檔案。拾光不會要求格式化來源卡或現有工作磁碟；請勿為了試用內測版，改變唯一份素材所在媒體的格式。

## 隱私權與網路

- 素材掃描、複製、檢驗與專案記錄預設在本機完成。
- 拾光不會將照片或影片上傳到「拾光」伺服器。
- 若將 NAS 或第三方同步資料夾設為目標，後續網路傳輸或雲端同步由對應的系統或服務提供者完成。
- 啟用自動更新後，應用程式會連線到官方更新來源；發現新版本時只會提醒，不會在轉存或封存中自動安裝。

## 回報內測問題

請前往 [Issues](https://github.com/Sorasukiawa/shiguang/issues) 提交問題或建議。建議附上拾光版本、macOS 版本、Mac 晶片型號、來源卡與目標磁碟格式、重現步驟與完整錯誤文字。截圖請先遮蔽客戶名稱、專案名稱與本機路徑。

請勿在 Issue 中上傳原始素材、客戶資料、私密路徑或其他敏感資訊。
